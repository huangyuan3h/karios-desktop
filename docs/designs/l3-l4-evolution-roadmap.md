# L3 → L4 升级路线图（2026-08-07 立）

> **何时看**：系统下一步升级方向的唯一真值。拍 L3/L4 相关需求、排期、拍板时先看这里。
> **何时不看**：单个任务的落地实现（→ `optimization-checklist.md` OPT-xxx / `trading-improvement-checklist.md` TIP-xxx）；产品级战略（→ `todo.md` §16）。
> **状态**：方向已拍板（2026-08-07）。L3 为当前目标，L4 为长期愿景。

---

## 1. 交易系统分级定义

| 级别 | 定义 | 关键能力 |
|------|------|----------|
| **L0** | 手动看盘 | 消息 / 直觉 / 无记录 |
| **L1** | 数据辅助 | 行情 + 指标 + 提醒，决策仍靠人 |
| **L2** | 纪律化决策 | 信号 + 执行闸 + 仓位规则 + 决策日志，**规则先行、人有最后否决权** |
| **L3** | 验证闭环 | 回测 / 纸面交易 / 成本与滑点建模 / 归因复盘 / 参数敏感度 → **每个信号值多少钱是可度量的** |
| **L4** | 执行闭环 | 券商 API 对接 + 半自动下单 + 执行回执 + 自动对账 + 组合级实时风控（相关性 / 共振熔断） |

## 2. 当前定位评估：L2.5（2026-08-07 评估）

**已是 L2+ 的证据**：

- 完整交易漏斗：TV 宇宙 → 回撤过滤 → TrendOK → Watchlist → 主线/Gate/Anti-Spike → 仓位硬闸（TIP-001~008 全落地）
- 多供给通道：TV、Alpha Radar、研报→Alpha（TIP-012）
- 执行闸门状态机：ATTACK / WEAK_ATTACK / HOLD_ONLY / DEFEND + V6.3 溢出豁免 + 14:30 时间锁 + 防守双轨
- 风险平价开仓：0.5% 风险预算 / 止损距离（V7.0-02）
- 度量雏形：漏斗转化率（TIP-002）、开火来源归因（TIP-011）、Alpha 映射 Auto-QA（TIP-009）、paper v0.1（CN-only）

**缺 L3 的差距（为什么是 2.5 不是 3）**：

1. 无有效回测验证——策略参数（score≥85、回撤 [-15%,-5%]、TrendOK 阈值）无统计显著性与过拟合检验
2. Paper 仅 CN、无滑点 / 手续费 / 涨跌停 / T+1 成本建模 → 胜率口径偏乐观
3. 卖出侧弱于买入侧：有 Chandelier/止损/目标，但无卖出归因复盘（卖早 / 卖晚 / 卖对）
4. 组合级风控缺位（V7.0-01 相关性热力网暂缓中）
5. 决策 Agent M1 已落地，但未接入 paper/归因数据做复盘

## 3. L3 目标：验证闭环（当前目标 · 预计 8-12 周）

### 3.1 L3 完成判定（Definition of Done）

- [ ] Paper 覆盖 CN + HK，含滑点、佣金、印花税、T+1、涨跌停、停牌建模，成交假设统一（signal price vs 收盘价 vs 次日开盘价）
- [ ] 回测引擎与 live Execution Gate **同口径**（同一份规则代码，非重写），可跑 ≥5y 历史
- [ ] 参数敏感性报告（score 阈值 / 回撤区间 / TrendOK 参数）——区分真 edge 与过拟合
- [ ] 卖出归因分桶上线（卖早 / 卖晚 / 卖对），Chandelier 质量可量化
- [ ] 周度自动复盘报告（决策 Agent M2 驱动，喂 paper 实绩 + 归因数据）
- [ ] 每个策略数字都有出处：规则 → 文档 → 测试 → 历史样本量的引用链

### 3.2 里程碑拆解

| 里程碑 | 内容 | 依赖 | 预估 | 衔接现有 |
|--------|------|------|------|----------|
| **L3-P1 度量基座** | paper v0.2：HK 接入（FX/T+0 结算建模）+ 成本/滑点参数表 + 成交假设统一；paper 胜率口径修正 | §8 paper v0.1 已有 | 2-3 天 | §8 P1；`paper_trading.py` |
| **L3-P2 回测引擎** | 与 live 同口径回测（复用 Execution Gate / TrendOK 代码路径）；5y 历史 bars；单策略参数敏感度视图 | L3-P1 | 4-6 天 | §8 P0 重启前置条件已齐 |
| **L3-P3 归因与敏感度** | 卖出归因分桶；参数敏感性报告（score / 回撤 / TrendOK）；卫星仓上限复核（15%/30%/sleeve） | L3-P2 | 3-5 天 | TIP-011 买入归因已有；§3 P1 |
| **L3-P4 决策 Agent M2** | 周度复盘：喂 paper 实绩 + 归因 + 漏斗数据，输出「本周决策质量报告」 | L3-P1/P3 | 2-3 天 | TIP-015 M1 已落地 |
| **L3-P5 组合风控** | V7.0-01 相关性热力网落地（Correlation Cap + 共振预警） | L3-P2 | 2-3 天 | V7.0-01 暂缓中，此处转正 |

> **L3 红线**：回测只做「参数敏感度」与「规则假设验证」，不做参数寻优工程（避免过拟合）；回测结论不作单独发布依据，以 paper 实绩为准。

## 4. L4 目标：执行闭环（长期愿景 · 6-12 个月 +）

### 4.1 L4 完成判定（Definition of Done）

- [ ] 券商 API 对接 ≥1 家（华泰 / 同花顺 / 东财 / 其他），完成沙箱验证
- [ ] 信号 → 人工确认 → 下单 → 执行回执 → 自动对账 全链路可用（**人类确认是硬前提，不做无人值守**）
- [ ] 组合级实时风控：相关性 cap、持仓共振熔断、盘中风险预算检查
- [ ] 美股 / 加拿大市场接入（时区 / 交易日 / 结算模型）
- [ ] 决策 Agent 升级为「执行监督」：持仓与信号背离时告警（不做自动执行）

### 4.2 里程碑拆解

| 里程碑 | 内容 | 依赖 | 预估 | 备注 |
|--------|------|------|------|------|
| **L4-P1 券商研究** | 券商 API 矩阵（可用性 / 合规 / 费率 / 沙箱）；确定 ≥1 家试点 | — | 1-2 天调研 | 输出决策文档，未拍板前不动代码 |
| **L4-P2 半自动下单** | 确认式下单：UI 确认 → broker API → 回执入库；失败重试 / 幂等 | L4-P1 | 3-5 天 | 先小额实盘 |
| **L4-P3 组合风控实时化** | V7.0-01 相关性与 L3-P5 的能力盘中化 + 熔断规则 | L3-P5 | 2-3 天 | |
| **L4-P4 自动对账** | 券商持仓 ↔ 本地 Watchlist 每日对账；异常告警 | L4-P2 | 2-3 天 | |
| **L4-P5 多市场执行** | US / CA 数据 + 时区调度 + 执行 | §9 P3 数据源先行 | 远期 | 依赖 §7 多市场推进 |

> **L4 红线**：
> - **人永远在环**：任何自动下单必须经人工确认；确认前置条件（闸门、仓位、相关性）缺一不可
> - 券商对接先沙箱后小额，不追求速度，追求「回执-对账」可信
> - 不引入杠杆 / 期权等复杂品种，卫星仓纪律定位不变

## 5. 升级原则（红线，不可漂移）

1. **人始终在环**——L3/L4 只是把「度量」和「执行管道」自动化，决策权与最终确认权保留给人
2. **先验证后执行**——L3 的验证闭环是 L4 执行闭环的前置，不允许跳过（否则执行管道建立在未经验证的信号上）
3. **同口径是铁律**——回测 / paper / live 必须共享同一份规则代码，杜绝三套口径三套结论
4. **卫星仓定位不变**——核心仓仍在系统外；信号再强也不等于全家 all-in
5. **每个里程碑交付「证据」**——完成判定必须可勾选、可引用（测试 / 报告 / 归档链接），todo 不假装完成
