# Family Hub 2027 — 家庭投资平台长线架构（设计稿 · 2026-08-14 用户拍板方向）

> 状态：**拍板中的设计草稿**（docs/designs/ 容器）。落地顺序见 §7 路线图。
> 用户核心原则：**「我去实现这些最重要的是财富；财富来自数据，数据说话」**——
> 一切架构决策以"数据可积累、可回测、可验证"为最高优先级。

## 1. 愿景

- 家庭在加拿大，一台 **Mac mini / Mac Pro 长期开机**，运行所有自研软件：
  财富（Karios）· 健康 · 家庭规划 · 写代码的 agent（opencode）等。
- 用户四处旅游，**入口是手机/平板（苹果生态）**，**通过说话控制全局**，
  agent 帮打理一切。
- 实现时间：**未来一年**（2026-08 → 2027-08）。

## 2. 核心架构判断

**不开发原生 App。** 原因：
1. 苹果生态的语音原生通道是 **Siri Shortcuts**（可调任意 HTTP API），原生 App
   不带来语音优势；
2. 个人/家庭项目维护成本（发版/审核/双端）远超收益；
3. 若未来发现 PWA+Shortcuts 不够 → 用 **Capacitor 包装现有 Web**（1-2 周），
   绝不复写。

```
手机/平板（唯一入口）
 ├─ 主屏 PWA 图标（浏览/操作全部软件）
 ├─ Siri Shortcuts（语音："Hey Siri，今天买什么"）
 ├─ PWA 内语音按钮（深度语音对话，Web Speech）
 └─ Bark 推送（系统主动说话）
        │
        ▼
    统一中枢 API（每项目 /v1/* + 统一"语音指令 API"）
        │
        ▼
加拿大 Mac mini（长期开机）：财富 / 健康 / 家庭规划 / opencode agent
```

## 3. 三个核心维度（用户口径）

| 维度 | 现状 | 目标 |
|------|------|------|
| **投资情况**（财富） | Karios Web + Bark 推送已打通（OPT-115） | PWA 主屏入口 + 语音查询 + 推送全链路 |
| **连接 Agent** | `/v1/*` agent API + webhook 事件已建 | 家庭 agent 对话层：自然语言 → `/v1/*` → 回答 |
| **代码 agent（opencode）** | 本机运行，任务手动触发 | 任务队列 API：手机下发 → Mac 执行 → Bark 回执 |

## 4. 关键组件

### 4.1 语音指令 API（Phase 1 核心新建）
- `POST /api/voice`：自然语言 → LLM 路由 → 调各项目 API → 返回 **TTS 友好短文本**。
- 一次建设，多处复用：Siri Shortcut / PWA 语音按钮 / 未来任何入口。
- 输出规范：一句话结论 + 关键数字（播报友好），详情走链接。

### 4.2 家庭服务器（Phase 2）
- 加拿大 Mac mini 部署（触发：总资产 +20% 里程碑或提前）。
- 备份/迁移复用 OPT-061 方案；Tunnel（cloudflared）做远程访问。
- 认证：家庭共享账号 + token（语音 API 需鉴权）。

### 4.3 多域整合规范（Phase 2）
- **接口先于项目**：每个新项目先定义 `/v1/*` + webhook 事件。
- Karios 是 hub：聚合各域通知（统一进 Bark + 通知中心），各项目不做独立入口。

### 4.4 Agent 层（Phase 3）
- opencode 任务队列 API：手机提交"跑对账 / 跑回测 / 执行任务" → Mac 上 agent 执行 → 结果推 Bark。
- 家庭 agent：一个 LLM 编排全部域（财富/健康/家庭/代码）。

## 5. 三条原则（防跑偏）

1. **不开发原生 App**——Phase 3 后仍不足才用 Capacitor 包装，绝不复写。
2. **接口先于项目**——`/v1/*` + webhook 是跨项目契约，Karios 当 hub 不当孤岛。
3. **语音是 API 的皮**——`/api/voice` 一建，Siri、PWA 按钮、未来入口都接它。

## 6. 财富原则（用户口径，不可漂移）

- **财富来自数据，数据说话**：所有系统行为必须产生可积累、可回测的数据
  （user_trades / paper / alpha 快照 / 行为对账 / 回测基线）。
- 新功能先问"它收集什么数据、一年后能验证什么假设"——不能验证的交互层功能
  优先级低于数据层功能。
- 家庭平台的一切域（健康/家庭规划）同样适用：数据先于界面。
